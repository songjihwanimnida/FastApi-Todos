# Spec: 할 일 마감일
Author: songjihwan. Date: 2026-10-27. Status: draft.
Intent: [intent.md](./intent.md)

## 요약
할 일에 날짜만 있는 선택 필드 `due_date` 를 추가한다. 서버는 저장·검증만 하고, "기한 지남" 판단과 표시는 화면(브라우저)이 사용자 컴퓨터 날짜로 한다. 목록 순서, 완료 처리, 진행률은 바꾸지 않는다.

## 요구사항

### 데이터·API (`fastapi-app/main.py`)
- **R1** 할 일에 선택 필드 `due_date` 를 둔다. 값은 날짜(시간 없음) 또는 `null`이고 기본값은 `null`이다.
- **R2** `POST /todos`, `PUT /todos/{id}` 는 `due_date` 로 `"YYYY-MM-DD"` 문자열이나 `null` 을 받는다. 생략하면 `null` 이다.
- **R3** 아래 값은 422로 거부하고 저장하지 않는다: 없는 날짜(`"2026-02-30"`), 형식이 다른 문자열(`"2026-1-5"`, `"20261031"`), 시간이 붙은 값(`"2026-10-31T00:00:00"`), 빈 문자열 `""`, 숫자(타임스탬프). 지난 날짜는 허용한다. 연도 범위는 0001–9999(Python `date` 범위)이며 따로 제한하지 않는다.
- **R4** `GET /todos`, `POST`, `PUT` 응답의 모든 할 일에 `due_date` 를 항상 넣는다. 값이 없으면 `null` 이다.
- **R5** `todo.json` 에는 `"due_date": "2026-10-31"` 또는 `null` 로 저장하고, 다시 읽으면 같은 값이 나와야 한다.
- **R6** 기존 `todo.json` 은 그대로 읽혀야 한다. v3 목록 형식과 v4 형식 모두 해당하며, `due_date` 가 없는 항목은 `null` 이 된다. 따로 이관 작업은 하지 않는다.
- **R7** PUT 은 지금처럼 전체 교체다. `due_date` 를 생략하면 `null` 로 지워진다. 마감일을 지키는 일은 화면이 맡는다(R9).
- **R8** API 버전을 `4.0.0` → `4.1.0` 으로 올린다. 필드를 추가하기만 하므로 마이너 버전을 올린다.

### 화면 (`fastapi-app/templates/index.html`)
- **R9** 화면에서 보내는 모든 PUT 에는 현재 `due_date` 를 담는다. 완료 체크와 완료 취소는 기존 값을 그대로 보내고, 편집은 폼의 값을 보내며 비우면 `null` 을 보낸다.
- **R10** 추가·편집 폼에 날짜 입력칸(`<input type="date">`, 라벨 "마감일")과 "지우기" 수단을 둔다. 편집할 때는 기존 값을 채우고, 연속 등록 후에는 우선순위처럼 비운다.
- **R11** 날짜를 덜 입력했거나 잘못 입력한 상태(`validity.badInput`)로 제출하면 막고, 입력칸에 포커스를 준다. 빈 값으로 조용히 저장되면 안 된다.
- **R12** 미완료 항목에 마감일이 있으면 우선순위 표시 옆에 연도까지 보여준다. 형식은 `2026년 10월 31일` 이다.
- **R13** 미완료이고 마감일이 오늘보다 이전이면 날짜를 빨간색으로 바꾸고 "기한 지남" 글자를 함께 표시한다. 마감일 당일은 평소처럼 보이고, 다음 날부터 기한 지남이다. "오늘"은 브라우저의 로컬 날짜로 정한다.
- **R14** 기한이 지난 항목은 체크 버튼의 접근성 이름에도 "기한 지남"을 넣는다. 예: `우선순위 1 기한 지남 과제 제출 완료`.
- **R15** 완료됨 섹션에서는 마감일을 보여주지 않는다. 데이터는 그대로 남아서, 완료를 취소하면 마감일이 다시 보인다.
- **R16** 목록 순서(우선순위 → id)와 진행률 표시는 바꾸지 않는다.
- **R17** 탭에 다시 돌아오면(`visibilitychange` 로 보이게 될 때) 목록을 다시 그려 "오늘"을 새로 계산한다. 자정을 넘겨 켜 둔 페이지도 돌아오면 맞게 보인다.

## 설계

**백엔드**
- `TodoIn` 에 `due_date: date | None = None` 을 추가한다. `TodoItem` 과 `TodoStore` 는 상속받으므로 그대로 둔다.
- 엄격 모드(`strict=True`)는 유지한다. JSON 요청에서 Pydantic 의 엄격 날짜 검증이 R3 을 그대로 충족한다(아래 검증 결과 참고).
- **불러오기**는 JSON 모드 검증(`model_validate_json`)으로 바꾼다. v3 목록 형식을 `{"todos": [...]}` 로 감싸는 처리는 유지한다.
- **저장**은 JSON 직렬화 모드(`model_dump(mode="json")`)로 바꾼다. 들여쓰기와 `ensure_ascii=False` 는 그대로 둔다.

**화면**
- 날짜는 화면 전체에서 `"YYYY-MM-DD"` 문자열로만 다룬다. `Date` 객체로 바꾸지 않는다.
  - 오늘 날짜는 `getFullYear/getMonth/getDate` 로 직접 만든다.
  - 기한 지남은 `due < today` 문자열 비교로 판단한다(형식이 같으면 사전순 비교가 곧 날짜 비교다).
  - 표시는 문자열을 `-` 로 나눠 조립한다.
- 날짜 계산은 순수 함수로 분리한다: `todayLocal()`, `isOverdue(todo, today)`, `formatDue(due)`.
- 표시 요소는 우선순위 표시와 같은 줄에 두는 `due-tag` 다. 달력 아이콘과 날짜를 넣고, 기한이 지났으면 `data-overdue="true"` 를 붙여 `var(--danger)` 색과 "기한 지남" 글자를 더한다.

**API 예시**
```json
// POST /todos 요청
{"title": "과제 제출", "priority": 1, "due_date": "2026-10-31"}
// 응답 201
{"id": 5, "title": "과제 제출", "description": "", "completed": false, "priority": 1, "due_date": "2026-10-31"}
```

## Open questions (intent 에서 이어진 것)

intent 의 질문은 모두 답이 나왔다. 오늘 기준은 사용자 컴퓨터 날짜, 기한 지남은 다음 날부터, 표시는 연도까지, 완료됨 섹션에는 마감일을 숨긴다. 구현 전에 정할 것은 아래와 같다.

1. **표시 형식** — 결정(2026-10-27): `2026년 10월 31일`. 연도까지 표시하고 스크린리더로 읽기에도 자연스럽다(R12).
2. **자정이 지나도 페이지를 켜 둔 경우** — 결정(2026-10-27): 탭에 돌아올 때 다시 그린다(R17).
3. **비현실적인 연도**(`0001-01-01`, `9999-12-31`) — 결정(2026-10-27): 제한하지 않는다(R3). intent 가 지난 날짜를 허용하고, 막을 기준도 따로 없다.
4. **화면 테스트** — 결정(2026-10-27): 커밋 33dfed3 에서 삭제된 Playwright 테스트 구조를 되살려 마감일 UI 테스트 파일 하나를 만든다(검증 계획 참고).
5. **UI 테스트 대상 서버** — 결정(2026-10-27): 기본 `BASE_URL` 을 `http://localhost:8000` 으로 바꾼다. 배포 서버는 `BASE_URL=http://163.239.77.77:5006` 처럼 환경변수로 지정한다. 예전 기본값은 배포 서버였지만, 마감일 기능은 배포 전에는 그 서버에 없다.

열린 질문은 더 없다.

## Areas of concern

**1. 지금 `load_store()` 로는 마감일이 들어간 파일을 읽지 못한다.** (확인함, pydantic 2.14.1)
`load_store()` 는 `json.loads` 로 만든 dict 를 `TodoStore(**data)` 로 검증한다. 이것은 Python 모드 검증이라 `strict=True` 에서 문자열 `"2026-10-31"` 을 `date_type` 오류로 거부한다. 필드만 추가하면 마감일이 있는 할 일을 처음 저장한 뒤부터 **모든 요청이 500** 이 되고, 파일을 손으로 고치기 전까지 앱을 쓸 수 없다. 기존 테스트는 `due_date` 를 쓰지 않으므로 이 문제를 잡지 못한다. 그래서 JSON 모드 검증으로 바꿔야 한다. `model_validate(..., strict=False)` 도 통하지만, 다른 필드의 엄격 검증까지 풀리므로 쓰지 않는다.

**2. 지금 `save_store()` 로는 날짜를 저장하지 못한다.** (확인함)
`json.dumps(store.model_dump())` 는 `date` 객체를 만나면 `TypeError: Object of type date is not JSON serializable` 을 낸다. 파일을 쓰기 전에 실패하므로 데이터가 깨지지는 않지만, 마감일이 있는 POST·PUT 은 모두 500 이 된다.

**3. PUT 전체 교체 때문에 마감일이 조용히 지워질 수 있다.**
- 화면의 완료 체크는 `{ ...todo, completed }` 로 보낸다. `todo` 가 `GET` 결과라 `due_date` 가 따라가므로 지금 구조로도 안전하다.
- 편집은 `{ ...todo, ...values }` 다. `values` 에 `due_date` 가 빠지면, 사용자가 마감일을 지워도 기존 값이 남는다. 지울 때는 반드시 `null` 을 명시해야 한다(R9).
- 마감일을 모르는 클라이언트(Swagger 에서 직접 호출, 캐시된 옛 `index.html`, 스크립트)가 PUT 하면 마감일이 지워진다. `priority` 도 지금 같은 방식으로 동작하므로(`test_update_todo` 참고), 의도된 방식으로 문서화만 한다.
- **탭 두 개 문제**: 잠금이 없고 마지막 쓰기가 이긴다. 탭 A 에서 마감일을 넣은 뒤, 새로고침하지 않은 탭 B 에서 완료 체크를 하면 B 의 옛 상태(`due_date: null`)로 덮여 마감일이 사라진다. 기존에도 있던 문제지만 지워질 수 있는 필드가 하나 늘었다. 이번 범위에서는 고치지 않는다.

**4. 날짜 로직이 자동 테스트의 사각지대에 있다.**
기한 지남 판단, 표시 형식, PUT 에 `due_date` 를 담는 일은 모두 `index.html` 의 JS 에 있다. 그런데 `ui_tests/` 는 커밋 33dfed3 에서 삭제됐고, SonarQube 도 `*.html` 을 분석에서 뺀다. 그래서 회귀가 생겨도 CI 가 잡지 못한다. 대책으로 Playwright UI 테스트 하나를 되살린다(Open question 4). 다만 이 테스트는 실행 중인 서버와 Chrome 이 있어야 해서 기본 `pytest`(`testpaths = ["tests"]`)에는 포함되지 않는다. 따로 실행하지 않으면 여전히 회귀를 놓칠 수 있다.

**5. 브라우저 날짜 처리의 함정**
- `new Date().toISOString().slice(0, 10)` 은 **UTC** 날짜다. 한국(UTC+9)에서는 오전 9시 전까지 어제 날짜가 나와서, 기한 지남이 하루 늦게 표시된다.
- `new Date("2026-10-31")` 은 UTC 자정으로 해석되어, UTC 보다 느린 시간대에서는 하루 전 날짜로 보인다. 또 `new Date(y, m, d)` 는 연도가 0–99 이면 1900년대로 바꾼다.
- 그래서 날짜를 `Date` 객체로 바꾸지 않고 문자열로만 다룬다(설계 참고).

**6. `<input type="date">` 의 빈 값**
값이 없거나 **덜 입력한 상태**에서 `.value` 는 `""` 다. `""` 을 그대로 보내면 422(R3)가 나고, `null` 로 바꾸기만 하면 덜 입력한 날짜가 조용히 사라진다. 그래서 `""` 는 `null` 로 바꾸되, `badInput` 일 때는 제출을 막는다(R11).

**7. 빨간색이 이미 다른 뜻으로 쓰인다.**
우선순위 1 표시(`--p1`)와 삭제 버튼 hover(`--danger`)가 이미 빨간 계열이다. 우선순위 1 이면서 기한이 지난 항목은 빨간 표시가 두 개 나란히 보인다. 그래서 "기한 지남" 글자와 아이콘으로 구분하는 것이 필수다(색 외 구분은 intent 의 제약 조건이기도 하다).

**8. `todo.json` 이 git 에 올라가 있고, 되돌리기를 하면 마감일이 사라진다.**
- 처음 저장할 때 모든 항목에 `"due_date": null` 이 붙고 v3 → v4 형식으로 바뀌어, 추적 중인 `fastapi-app/todo.json` 에 큰 diff 가 생긴다. 커밋에 섞지 않도록 주의한다.
- 4.0.0 으로 되돌리면 옛 코드가 모르는 필드를 무시하고 읽는다(`extra` 기본값 `ignore`). 앱은 동작하지만 다음 저장 때 **마감일이 모두 사라진다.**

**9. 파일을 손으로 고칠 때의 위험이 커진다.**
`todo.json` 에 잘못된 날짜를 직접 써 넣으면 불러오기가 실패해 모든 요청이 500 이 된다. 잘못된 `priority` 를 써 넣을 때와 같은 기존 동작이지만, 날짜는 손으로 틀리기 쉬운 값이다. 이번 범위에서는 바꾸지 않는다.

  - R2 생성·수정 응답 왕복

- **테스트 작성 주의**: Python 에서 `TodoItem(due_date="2026-10-31")` 처럼 문자열을 넣으면 엄격 모드에서 실패한다. 픽스처는 `datetime.date(2026, 10, 31)` 을 쓴다.
- **Playwright UI 테스트** (`fastapi-app/ui_tests/`, 커밋 33dfed3 이전 구조를 되살림):
  - `conftest.py` 는 Playwright 와 API 부분만 되살린다: `BASE_URL`(기본값 `http://localhost:8000`, 환경변수로 덮어씀), 제목 접두어 `[UI테스트 …]` 로 테스트 항목만 만들고 지우는 `seed`/`cleanup`, 한국어 locale 브라우저 설정. Selenium 픽스처는 쓰지 않으므로 넣지 않는다.
  - `test_due_date_ui.py` 한 파일에서 브라우저를 `timezone_id="Asia/Seoul"` 로 열고, `page.clock` 으로 시각을 **2026-10-31 08:30 (KST)** 에 고정한다. 오전 9시 전이라 UTC 날짜로 계산하면 하루가 어긋나는 시각이어서, 우려 5 의 함정까지 함께 확인할 수 있다.
  - 확인할 것:
    - 어제 마감(10-30) 미완료 항목: "기한 지남"과 `2026년 10월 30일` 이 보이고, 빨간색이며, 체크 버튼 이름에 "기한 지남"이 들어간다 (R12–R14)
    - 오늘 마감(10-31) 미완료 항목: 날짜만 보이고 "기한 지남"은 없다 (R13)
    - 마감일 없는 항목: 날짜 표시가 없다
    - 완료된 항목은 완료됨 섹션에서 마감일이 보이지 않는다 (R15)
    - 어제 마감 항목을 완료했다가 취소한 뒤 API 의 `due_date` 가 그대로다 (R9)
    - 편집에서 마감일을 지우면 API 의 `due_date` 가 `null` 이 된다 (R9, R10)
    - 추가 폼에서 날짜를 넣어 등록하면 저장되고, 연속 등록 폼에서 날짜가 비워진다 (R10)
  - 실행 방법: `pip install -r requirements.txt -r requirements-ui.txt` (Windows 는 `PYTHONUTF8=1`) → 서버 실행 → `pytest ui_tests`.
  - 로컬 서버로 돌리면 추적 중인 `todo.json` 에 테스트 흔적(형식 변환, `next_id` 증가)이 남는다(우려 8). 커밋 전에 되돌린다.
- **수동 체크리스트** (자동화가 어렵거나 비싼 것만):
  - 덜 입력한 날짜는 제출이 막힘 (R11 — Playwright 로는 `badInput` 상태를 만들기 어렵다)
  - 실제 스크린리더로 "기한 지남"을 읽음 (R14)
  - 자정을 넘겨 켜 둔 탭에 돌아오면 기한 지남이 갱신됨 (R17)
