# Intent: v5.0.0 — 프로젝트, 하위 할 일, 반복, 검색·필터·정렬
Author: songjihwan. Date: 2026-11-17. Status: draft.

## Problem
할 일이 한 목록에 전부 섞여 있어서 개수가 늘수록 쓰기 어렵다.
- 과제, 업무, 개인 일을 나눌 곳이 없다.
- 원하는 할 일을 찾으려면 목록을 끝까지 훑어야 한다. 우선순위·마감일·상태로 골라 보거나 순서를 바꿀 수 없다.
- 여러 단계로 된 일은 설명 칸에 단계를 적고 머릿속으로 체크해야 한다.
- 매주 반복되는 일은 끝낼 때마다 같은 할 일을 다시 만들어야 한다.

## Proposed outcome
**프로젝트(목록)**
- 프로젝트를 만들고, 이름을 바꾸고, 삭제할 수 있다. 할 일마다 프로젝트를 하나 고르거나 고르지 않는다(수집함).
- 화면에서 프로젝트를 골라 그 프로젝트의 할 일만 보고, 프로젝트별 진행률을 본다. "전체"와 "수집함"도 고를 수 있다.
- 프로젝트를 삭제하면 그 안의 할 일도 함께 삭제된다. 확인 창에 지워질 할 일 개수를 보여준다.

**하위 할 일**
- 할 일 안에 하위 할 일(제목 + 완료 여부)을 추가, 체크, 삭제할 수 있다.
- 목록 행에 하위 할 일 진행 상황(예: 2/5)이 보인다.

**반복 할 일**
- 매일, 매주, 매월 반복을 고를 수 있다. 반복은 마감일이 있는 할 일에만 설정한다.
- 반복 할 일을 완료하면 지금 할 일은 완료로 남고, 다음 마감일로 같은 할 일이 새로 생긴다(제목, 설명, 우선순위, 프로젝트, 반복 유지, 하위 할 일은 체크 해제).

**검색·필터·정렬**
- 제목과 설명으로 검색한다(대소문자 무시).
- 프로젝트, 우선순위, 상태(진행 중/완료)로 거르고, 추가순·우선순위·마감일·제목 순으로 정렬한다.
- 서버 API(`GET /todos` 쿼리)로도 같은 검색·필터·정렬을 쓸 수 있다. "기한 지남" 필터는 화면이 사용자 컴퓨터의 오늘 날짜로 처리한다.

- v5.0.0으로 릴리즈한다.

## Out of scope
- 저장소 변경(SQLite 등). `todo.json` 파일을 그대로 쓴다.
- 여러 사용자, 로그인, 공유
- 하위 할 일의 하위 할 일(1단계만), 하위 할 일에 우선순위·마감일 넣기
- 드래그로 순서 바꾸기, 할 일을 다른 할 일 아래로 옮기기
- 매일/매주/매월 외의 반복(평일만, 격주, 특정 요일 여러 개 등), 반복 종료일
- 알림, 시간(시·분) 입력
- 페이지 나누기

## Affected users and systems
- 사용자: 할 일이 많아 나눠 보고 찾아야 하는 사용자, 반복되는 일이 있는 사용자
- API: `GET/POST/PUT /todos` 요청·응답에 필드 추가, `GET /todos` 쿼리 파라미터 추가, 프로젝트 API 신규
- `fastapi-app/main.py`, `fastapi-app/templates/index.html`(화면 구조가 크게 바뀜), `fastapi-app/todo.json` 저장 형식
- `fastapi-app/tests/test_main.py`, `fastapi-app/ui_tests/`, `jmeter/` 테스트 계획(기존 요청이 계속 통과해야 함)
- `RELEASE_NOTES.md`, `CLAUDE.md`, 태그 `version5.0`

## Constraints
- 기존 API를 쓰는 쪽이 깨지지 않는다. 제목만 보낸 `POST /todos`, 쿼리 없는 `GET /todos`(전체 목록)는 지금처럼 동작한다.
- `todo.json`의 v3 목록 형식과 v4 형식을 계속 읽는다. 기존 할 일은 수집함, 하위 할 일 없음, 반복 없음이 된다.
- PUT은 전체 교체를 유지한다. 화면은 체크만 바꿀 때도 프로젝트·하위 할 일·반복·마감일을 빠짐없이 보낸다.
- 엄격한 입력 검증(`strict`)을 새 필드에도 똑같이 적용한다. 없는 프로젝트 id, 마감일 없는 반복은 거부한다.
- 모든 읽기·쓰기는 `STORE_LOCK` 안에서 한다. id는 계속 `next_id`로 매기고, 지운 id는 다시 쓰지 않는다(프로젝트도 같다).
- 새 의존성은 추가하지 않는다. `/metrics`를 유지한다.
- 날짜는 `"YYYY-MM-DD"` 문자열로 다룬다. 색만으로 상태를 구분하지 않는다(글자, 스크린리더 이름 함께).

## Open questions
- 매월 반복에서 31일처럼 없는 날짜: 그 달 말일로 맞추는 안을 제안 (1/31 → 2/28 → 3/31).
- 다음 회차 기준일: 완료한 날이 아니라 원래 마감일 기준으로 제안. 오래 밀린 일은 다음 회차도 이미 기한 지남일 수 있다.
- 반복 할 일의 완료를 다시 해제하면 이미 만든 다음 회차는 그대로 둔다(자동 삭제 안 함)로 제안.
- 프로젝트 이름 중복 허용 여부: 같은 이름 거부(409)로 제안.
